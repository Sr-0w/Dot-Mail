# Optional instant notifications

Exact UI hooks on MailRepository:

- `val instantNotifications: Flow<Boolean>` observes the persisted preference.
- `suspend fun setInstantNotificationsEnabled(enabled: Boolean): Boolean` enables/disables it. Enable from the visible app with at least one account; false means the request could not start (background, no account, or platform refusal). Disable works from any app state.

The preference is AccountSettingsStore.sync.instantNotifications, off by default. The UI should explain: “Keeps an Inbox connection open for each account, including while the app is in the background. Uses an ongoing notification and may use more battery. Android battery/network restrictions can still delay mail.” Claude owns that toggle/explanation. No battery-exemption prompt or proprietary push dependency is added.

InstantIdleService is unexported, uses foregroundServiceType=specialUse on Android 14+, declares both foreground-service permissions and the required subtype explanation, and immediately posts a low-importance ongoing notification with the battery trade-off, launcher tap and Stop action. Stop clears the setting; removal of all accounts also stops/disables it. The service starts from a visible app, persists through backgrounding while enabled, and supports system sticky restart. There is no boot receiver: after a device reboot it resumes when the app is next opened. This follows [Android foreground service type requirements](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use).

A single graph-owned IDLE coordinator runs when the app is visible OR this service is running. Handoffs do not duplicate/restart sockets. Per-account reconciliation ignores sync-status/name writes; changed credentials/auth state affect that account only. Validated network callbacks close/reopen sessions on loss/handover and respect the unmetered-network setting. Reconnect backs off from 30 seconds to 15 minutes; IDLE renews after 25 minutes. Servers without IDLE remain on periodic sync rather than reconnecting continuously. Auth failures surface as SyncState.Error(isAuthError=true). Cancellation closes sessions and unregisters network callbacks. Ordinary periodic sync remains WorkManager-based. Immediate/IDLE jobs now carry `scheduled=false`; this also fixes interval/manual-only gating incorrectly suppressing IDLE-triggered work. Periodic jobs retain their interval/manual-only checks.

Validation: scripts/gw :mail:test :data:testDebugUnitTest :app:compileDebugKotlin. Tests inject network/account changes and session lifetimes to verify no status churn, sibling isolation, disconnect/reconnect, unsupported IDLE, unmetered policy, auth errors and bounded retry. GreenMail additionally verifies real IDLE delivery callbacks, unread preservation and prompt cancellation. Robolectric API 34 tests cover default-off, foreground notification/channel/battery text/Stop, public enable-disable API and unexported specialUse manifest. Release shrinking/build is checked separately before PR. No schema/dependency change, live-account write, emulator install or phone access. Physical-device foreground-service/Doze behavior still needs Claude's smoke test; test doubles do not prove OEM battery behavior or actual background delivery latency.
