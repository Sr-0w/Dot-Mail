# iTIP attendee replies

ComposeRepository.sendCalendarReply(messageId, Ics.PartStat): Long queues a response through the normal outbox and returns its id, with a five-second undo window. Supported responses are ACCEPTED/TENTATIVE/DECLINED. The cached invitation is parsed locally (bounded to 512 KiB per calendar part); there must be exactly one active REQUEST inviting an identity of the message's account. Non-invited, cancelled, ambiguous and NEEDS_ACTION cases are refused. The invited identity sends only to the organizer, retaining UID, SEQUENCE and threading headers through Ics.reply. Removing/changing that alias before delivery cannot silently fall back to another sender.

MIME is multipart/alternative with UTF-8 human text and a base64-encoded text/calendar; charset=UTF-8; method=REPLY part. Reply metadata is stored in the outbox JSON, surviving process death and retries. SMTP uses the existing account envelope sender and Sent-copy behavior. Undo cancels the response without creating a misleading ordinary-text draft. The original invitation is retained. No schema/dependency change.

Validation: scripts/gw :mail:test :data:testDebugUnitTest :app:compileDebugKotlin. A MIME round-trip test verifies the calendar alternative and encoding; GreenMail tests cover all three responses, alias/organizer routing, UID/sequence, actual SMTP delivery, cancellation, rejection and removed-alias handling. Calendar test fixtures reset AndroidX FileProvider's static path cache because Robolectric uses a different filesDir for each test. GreenMail includes Sent copies in receivedMessages; delivery assertions deduplicate by Message-ID. No phone or live mailbox access.
