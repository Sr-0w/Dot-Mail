## Requested UI review

Scope: `ThreadScreen.kt`, `HtmlMessageView.kt`, `ComposeViewModel.kt`, `MainActivity.kt`, with supporting contract/data paths. Source review only. The Codex Security capability preflight was ready, but the managed scan service was unavailable in this session, so no formal managed scan/artifacts were generated. This is the engineering review requested by Claude.

Concrete initial findings sent to Claude and subsequently fixed by him:

1. `MainActivity` initialized its lock state to false and only loaded the lock preference for `savedInstanceState == null`. Recreating/rotating while the app lock was showing bypassed that boundary. Lock state now survives recreation.
2. External `ACTION_SEND` streams accepted `file://` paths, which `cacheAttachments` opened under Dot Mail's own UID. A malicious sharing app could prefill a private app file and an attacker recipient, causing autosave to snapshot privileged data for a later user-assisted send. External shares now accept only content URIs excluding our FileProvider authority; the data layer additionally rejects all non-content attachment URIs. A regression test checks that private file URIs cannot be imported.
3. Autosave/send/discard/close could overlap, and repeated send taps had no guard. This could duplicate queued messages, save stale drafts, or lose the final close save when the ViewModel scope ended. Claude added serialized draft mutation, a finished guard, and app-scope final save.

Additional actionable notes sent to Claude:

- `SafeClient`'s blanket content/data passthrough was broader than its stated policy. Current sanitizer plus current-message CID maps are a mitigating control; no direct exploit through sanitized email HTML was established. Prefer an exact set of current-message CID URIs, serve only those through interception, and disable native content access. Claude updated this to an exact inline URI allowlist with native content access disabled.
- Switching sender account while retaining a saved draft's localId conflicts with account ownership validation. Save a copied draft under the new account and discard the old one only after success. Data attachment import now copies across account directories rather than depending on files removed with another account.
- Outbox retry/delete return false on state/processing races; UI should show a busy/state-changed message instead of silently ignoring false.
- Large HTML sanitization should run on Default, not inside a Main-thread `remember` computation.
- `ThreadViewModel.act`/`onOpened` launch repository actions without handling local validation failures (e.g. missing Archive role). Catch these and surface a message instead of an uncaught ViewModel coroutine exception.

Positive controls checked: raw HTML always goes through the sanitizer; CID maps are drawn from the current message; JS/file access is disabled; network is blocked before opt-in; external link opening has a scheme allowlist and destination confirmation; attachment sharing grants read access to a FileProvider URI; notification extras use the agreed Long thread ID. Remaining UI changes belong to Claude; I did not edit UI files.

## Minimal outbox review contract

Implemented in the existing ComposeRepository:

```
val outbox: Flow<List<OutboxItem>>
suspend fun retrySend(outboxId: Long, confirmPossibleDuplicate: Boolean = false): Boolean
suspend fun deleteOutbox(outboxId: Long): Boolean
```

`OutboxItem`: id, accountId, subject, recipients, sendAt, state, error, canRetry, canDelete. States: QUEUED, SENDING, SAVING_SENT, NEEDS_REVIEW. Completed/cancelled/deleted entries disappear. Claude has already added the consuming UI.

Uncertain SMTP cannot be requeued without explicit duplicate-risk acknowledgement. A confirmed retry reuses the persisted MIME/Message-ID. Connection failures before submission are automatically retryable. SAVING_SENT retries only APPEND, never SMTP. The APPENDING claim prevents deletion while a server copy is being written; interrupted APPENDING recovers to APPEND, while interrupted SUBMITTING recovers to UNCERTAIN. Recovery shares the delivery lock so startup cannot relabel a newly running send. Scheduled/undo sendAt is preserved by retry. Delete removes the local queue/review item and never recalls remote mail. Booleans reject stale/ineligible actions.

No outbox schema change was needed. New regression tests cover observation, active-delivery protection, explicit acknowledgement, schedule preservation, deletion, recovery, and Sent-copy retry without a second SMTP delivery.

## Snippet prefetch

Added `MailClient.snippets(...)` and `SnippetFetcher`: inspect BODYSTRUCTURE, prefer first non-attachment text/plain part, otherwise text/html; request **UID FETCH BODY.PEEK[section]<0.2048>**. UID addressing avoids unrelated EXPUNGE sequence-number races. Decode charset and transfer-encoding prefixes (including incomplete base64/quopri tails); derive visible previews with Qwen's Snippets helper. No full-body API or attachment stream is touched.

Sync considers the newest 200 cached messages per folder and fetches only those missing a preview/full body. A failed preview request does not discard successful header/flag sync. Preview completion is persisted independently from `bodyLoaded`, including legitimately empty snippets, so empty results are not redownloaded every 15 minutes. Full body loads also use the same snippet helper.

Room version 2 adds `snippetFetched INTEGER NOT NULL DEFAULT 0`; explicit migration 1→2 preserves the cache and credentials. Tests exercise bounded text selection, HTML/base64 prefixes, no Seen change, no full-body cache population, and an actual v1→v2 Room open/validation.
